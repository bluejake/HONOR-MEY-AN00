## 1 固件包结构与提取链路（已定案）

**外层**（11,442,338,777 B，7 条目，`ReleaseDoc/` 4 + `Software/dload/` 3，全部 STORE 未压缩）：

| dload 包 | 大小 | 角色 |
|---|---|---|
| `update_sd_base.zip` | 9,326,813,703 B | base 层（100 条目） |
| `update_sd_preload_MEY-AN00_all_cn_R404.zip` | 2,120,024,825 B | 预装层 |
| `update_sd_cust_MEY-AN00_all_cn.zip` | 194,715 B | 运营商定制层 |

**内层不是标准 zip**：荣耀专有容器（头部 `84 b6 03 90 …`，含 `b6 6d`/`bb bb`/`dd dd`/`ee ee` 重复模式 = XOR 混淆痕迹）。经自研解包脚本（`analysis/scripts/`：`honor_extract.py` / `sparse2raw.py` / `erofs.py` / `erofsz3.py`，纯 Python 无第三方依赖）逐层剥离。

**提取链**：外层 zip → dload 三包 → 专有容器解出 17 个分区镜像（`analysis/output/c_line/image/`）→ sparse（magic `0xED26FF3A`, blk 4096）→ raw → EROFS 逐分区解析。

**★ 决定性物证（内核 sha256 完美印证）**：

```
SOFTWARE_VER.mbn      = "MEY-LGRP1-CHN 10.0.0.175"        ← 与设备完全一致
sha256(固件包 boot.img 内核) = e8ce5dbf…2906f9c79
sha256(analysis/scratch/Image-mey) = e8ce5dbf…2906f9c79  ← IDENTICAL
```

⇒ 此前基于 `Image-mey` 逆向推导的全部内核常量（`MEY_DIRECT_BOOTID_PARENT=0xffffff802a29b090`、`MEY_PHYS_DELTA=0x28000000`、stage0/stageB 几何）**获得官方物证背书**。

## 3 SELinux 与安全配置面

**策略文件**（`analysis/output/c_line/sepolicy/`）：`plat_sepolicy.cil` / `vendor_sepolicy.cil` / `system_ext_sepolicy.cil` / `precompiled_sepolicy`；
file_contexts（system、system_ext）已提取。**缺口**：`seapp_contexts`、vendor file_contexts 未提取（不阻塞结论，见 §7）。

**关键授权链（实测确认）**：
```
sys.oba.make.otg / sys.oba.block.name / sys.oba.copy.start / oba.debug_on ∈ oba_prop
(allow shell oba_prop (property_service (set)))     ← shell 域可写，设备实测 setprop rc=0
```

**用户态封锁实测**：`/proc/cmdline`、`/proc/kallsyms`、`kptr_restrict`、`dmesg_restrict` 等被收为 0400（非 AOSP 默认 0444）；
`/proc/config.gz` 可读（0444，缓解判定证据源）。
⇒ 修正旧结论：荣耀加固为**"部分关闭"**——自研 CFI/模块基址随机化/符号隐藏关闭，procfs 收敛开启。

**内核缓解实测（config.gz 7,787 行，结论：无任何一项直接阻断 `rb_erase` 数据写原语）**：

| 项 | 值 | 影响 |
|---|---|---|
| BTI_KERNEL | NOT SET | ★ 后续 ROP/BOP 无需 landing pad |
| CFI_CLANG / CFI_PERMISSIVE | y / NOT SET | 强制 kCFI ⇒ 伪造 fops 劫持函数指针须类型匹配（复用原生 `uhid_fops` 是正确策略） |
| RANDSTRUCT_FULL | NOT SET | ★★★ `file_operations` 偏移可靠 |
| INIT_ON_ALLOC_DEFAULT_ON | y | 伪数据须落在分配后窗口（实测非阻断） |
| INIT_ON_FREE_DEFAULT_ON | NOT SET | ★ 有利 |
| RANDOMIZE_BASE / RANDOMIZE_MODULE_REGION_FULL | y / NOT SET | 需先泄露 slide；模块区不满随机 |
| PTR_AUTH / PAN / MTE | y | 不阻断数据写 |
| SELinux | Enforcing | 不拦内核内部写 |

## 4 ★ 临时 Root 实现路径盘点（核心结论）

### 4.1 路径总表

| 编号 | 路径 | 类型 | 状态 | 结论 |
|---|---|---|---|---|
| U1 | OBA 属性链（`sys.oba.*` → root 脚本/init 内建） | 纯用户态 | **❌ 彻底关闭** | 三条子路径全部证伪（见 4.2） |
| U2 | `parse_kpatch /patch_hn/kpatch/insmod_list`（init insmod 内核模块） | 用户态+分区 | ⚠️ **自举悖论** | 详见 4.2；仅可作写原语成立后的巩固手段 |
| U3 | `mini_bugreport`(keycodes→root dumpstate) / `/data/update/**` 0777 / `usb_update_daemon` | 用户态 | ❌ 非提权 | dumpstate 输出仅日志面；0777 目录仅 OTA 数据污染；usb_update 仅强制重启 |
| K1 | CVE-2026-43499（rt_mutex PI 链） | 内核 | ⏸ **挂起**（10-02 起） | e70~e75 已把崩点收敛到 `rt_mutex_adjust_prio_chain` 主体（见 4.3） |
| **K2** | **CVE-2026-64560（`rb_erase` 红黑树写原语）** | 内核 | ★ **唯一主战场** | stage0 几何已实机双证；当前卡点 H10 已修待验证（见 4.4） |

**⇒ 总判定：临时 root 的唯一可行入口是运行时内核漏洞写原语（K2 主线），用户态无捷径。**
（硬约束背景：175 版已含 2026-08 安卓补丁 ⇒ 被覆盖的公开漏洞全排除；Bootloader 不可解锁 ⇒ 无 Magisk/fastboot 路线。）

### 4.2 用户态路径为何全灭（证据摘要）

**U1 OBA 属性链**（链条本身完整：`shell setprop sys.oba.make.otg=true` rc=0 → `start oba_service` root sh）：
1. `sys.oba.make.otg` → `oba_service`：被 `ro.oba.whenlocked=true` 前置阻塞，该属性在锁定启动下**从未被设置**（全镜像只读不写，由 bootloader/vendor_init 早期注入）；
2. `sys.oba.block.name` → `make_oba_otg`：仅 `ls`+`setprop`，无文件写；
3. `sys.oba.copy.start` → `oba_file_verify` → `libobaverify.so:0x24e0`：`min(w19,w20)` 长度截断缺陷**真实存在**，但通过校验**需要 RSA 私钥签名的 `honor_oba.cfg`** ⇒ 收益为零。
另 `oba.debug_on` → `hilogcat-early` 参数写死（`-t 1`），`xlogcat` 域无提权能力（实测 `/system_ext/bin` 对 shell 不可达）。

**U2 parse_kpatch**：`init.honor.update.rc` 中 `parse_kpatch /patch_hn/kpatch/insmod_list` 会 insmod 内核模块，若 `/patch_hn`（kpatch 分区）可写即内核代码执行。但：`kpatch.img` 前 64B 全零（出厂未用），且**写分区需要 root 本身** ⇒ 自举悖论。正确用法是 K2 写原语成立后，用它加载持久化/辅助模块（临时 root 目标下甚至不需要）。

### 4.3 K1（43499/rt_mutex）挂起状态与复活条件

e70~e75 决定性实验矩阵已证明：崩溃**必须**满足 `p->pi_blocked_on` = 伪 waiter（目标 pid 1/owner 均不崩）⇒ 崩点 100% 在 `rt_mutex_adjust_pi@0x1081438` → `rt_mutex_adjust_prio_chain` walk；`w3`（waiter prio）早退不可救——e73 用 w3=139 仍崩，因 `__sched_setscheduler@0x169894` 的 `pi_top_task` 钳位（`0x169e38~0x169e48 csel`）使 `p->prio = min(pi_top_task->prio, 139) ≠ 139`，该值由伪 waiter 自身决定 ⇒ **自指不可控，停止投入**。
复活条件（e76+）：攻坚 chain 主体四约束 + **owner 匹配安全出口 `0x1081c64`**（构造 `[w11+0x18] = p|1` 使 walk 干净返回，最优候选）。细节见 `HANDOFF.md`。

### 4.4 K2（64560/rb_erase）主线——当前唯一活跃路径

**写原语**：`timerqueue_del@0xffffffc08003f7d8` → `__rb_erase_augmented@0x…03a9d4`，Case1 写序
W1 `*(parent+0x08)=forged_child` → W2 `*(forged_child)=forged_parent` → `RB_CLEAR_NODE`。
触发路径 = `cleanup_timerqueue`（task 退出），载体 `posix_timers_cache`（264 B × 31/order-1 slab，RCU 延迟释放）。

**已实机双证的几何**（固件 sha256 背书）：
- stage0：`MEY_DIRECT_BOOTID_PARENT=0xffffff802a29b090`，W1 换 `ctl_table.data` → `/proc/sys/kernel/random/boot_id` 泄露 physmap 指针 ⇒ slide（实机第 74 次 attempt 命中 `slide=0x22c5600000`）；
- stageB：`uhid_misc`@off `0x22d7c00`、fops@0x10，forged_parent = `P0alias(misc_list)−8` ⇒ W1 写 `misc_list.next` → `open(/dev/uhid)` 建立读写桥。

**里程碑链**：`MISC_BRIDGE_READ_PASS → _OPEN_PASS → MISC_LIST_RESTORE_PASS → STAGE0_CYCLE_RESTORE_PASS → STAGE0_BOOTID_RESTORE_PASS → MISC_BRIDGE_RW_PASS → PIPE_RECLAIM → PHYS_PROBE → STAGE8_ROOT`

**当前卡点与修法**：stage0 官方基准 4/6 boots，MEY 实测 0/256 ⇒ 数量级差。10-05 定案真根因 **H10**：f77 缺失官方 `race_timing_slot()`/`dada_bridge_order[]`（36 项时序编排），`exec_delay_ns` 与官方 0/35 重合——**已注入并实机验证**（`timing_slot=13`、`exec_delay_ns=2947` ✓）。
判据纪律：**`MISC_BRIDGE_READ_PASS` per boot（官方 ≈1/8），Budget boots not parameter changes**；`changed_nodes=0` 不是失败信号。
已证伪/勿重复：H7（`exec_after_deleted` 官方真值=100）、H8（`send(8192)` payload 本来就是 order-1，sprayprobe 实测 97.5~101.5% 吻合）、H9（xcache_probe ratio 1.472，页池已对齐）、H2（`SCAN_DIAG zero=0`）。

### 4.5 临时 root 终态方案（K2 成立后）

1. stage0 泄露 slide → stageB 建立 `uhid` 读写桥 → PHYS_PROBE；
2. 直接改写当前进程 `cred`（uid/gid 0）或 `init` 的 cred 完成提权（RANDSTRUCT 未开 ⇒ cred 布局可静态确定）；
3. 判据 `read_stext OK leaked=ffffff…`；SELinux 域仍为 shell（临时 root 目标下无需域迁移；若需 domains 迁移再走 U2/magisk-style 均为后话）。

## 5 风险分级（固件侧残留面）

| 级别 | 项 | 说明 |
|---|---|---|
| 高（受阻塞） | `sys.oba.make.otg` → root `oba_service` | 链完整，需 `ro.oba.whenlocked=true`（正常启动不存在） |
| 高 | `parse_kpatch` insmod | 需先写 `/patch_hn` ⇒ 自举悖论，仅作后效巩固 |
| 中 | 20+ 个 `/data/update/**` 0777 | 任意 app 可写，OTA/COTA 数据污染面 |
| 中 | `fcme` → `hal_hwfactoryinterface` binder | 工厂 HAL 调用面（root 域 oneshot，shell 不可达） |
| 低 | `dlupserver`(bind 任意端口) / `dtshpxservice`(音频 HAL) / `fb_bypass` / `usb_update_daemon` | 非提权 |

## 6 差距与下一步

**差距**：① `seapp_contexts`、vendor `file_contexts` 未提取（对 shell→root 结论无影响）；② `kpatch.img` 全零区与 `patch_avb.raw` 未深析；③ H1/H4/H5 待重判（旧 `changed_nodes` 证据作废）。

**下一步（优先级）**：
1. **H10 验证**：读 `h10_r1.log`，确认 `timing_slot` 按 13,32,21,1,13,32,21,1,2,3… 推进；以 `MISC_BRIDGE_READ_PASS` per boot 计费（≈1/8），按官方「budget boots」策略打满开机轮次；
2. **stage0 0/256 解释**：优先查 KASLR 分支 `(seq-1)%16+1` slot 是否也需编排（官方 KASLR 走 16 循环）；
3. K1 并行线：e76「owner 匹配安全出口 `0x1081c64`」实验（条件允许时）；
4. 工具化：`sprayprobe`/`xcache_probe` 扩展为 `tools/fuzz_pages.sh`（尺寸×并发 → CSV）。
