> 生成时间：2026-10-05 00:2x

## 0. 一句话结论

**设备在 H90 开火后 35 秒从 Windows USB 总线彻底消失，至取证时已 70+ 分钟未重新枚举。**
正常重启会在 30–60 秒内重新枚举 ⇒ **这不是一次正常重启**。但「USB 不在」≠「手机坏了」，
需物理现象才能定性（见 §5）。

### 2.1 时间线的两个硬结论

**结论 A：H88 没有打死设备。**
H88 在 22:43:30 push 完就再没拿到设备日志（当时判「设备可能已重启」），
但 USB 层的 `LastArrivalDate` 仍是 22:22:29、`LastRemovalDate` 是 **23:16:48**——
说明 22:43 之后设备**从未从 USB 总线掉过**。H88 只是把 adbd/USB 传输层搞挂了
（`no devices` 但 PnP 仍 present），内核还活着，所以 H90 的 push 能成功。

**结论 B：★ H90 是那一次把设备打挂的开火。★**
H90 开火 23:16:13 → 设备移除 23:16:48，间隔 35 秒，**落在同一次开火窗口内**。

### 2.2 ★ 推翻 H91/HANDOFF 的「H90 未有效执行」结论

HANDOFF §2.5.5 与 MEMORY 记的是：

> 「设备端 `timeout 1500` 导致 toybox 无 applet ⇒ rc=255 + adb 掉线，exploit 根本没启动」

**这条结论是错的，两处证据：**

1. **`rc=255` 不是「command not found」的码。** toybox sh 遇未知命令返回 **127**，
   不是 255。255 是 adb 传输层错误码（device offline / disconnect）。
2. **若 exploit 根本没启动，设备不会在 35 秒后从 USB 总线消失。**
   一条 `rm -f` + 一条 `chmod` 不会拔 USB。

⇒ **修正记录：H90 的 exploit 确实启动了，并在 35 秒内导致设备失去 USB。**
H90 记为 **`LAUNCHED_THEN_LOST`（已启动，随后失联）**，不是「未执行」。

⚠️ 这一条同时意味着：**上一轮我告诉你「不能把设备异常归因于 H90」是错的，我撤回。**
设备状态与 H90 开火在时间上直接对应。

## 6. 本轮冻结的铁律级新规

**★ 新增铁律：开火前必须记录 Windows 侧 `LastArrivalDate` / `LastRemovalDate` 作为基线。**
理由：adb 层无法区分「重启 / USB 断连 / 驱动掉线」，但 PnP 的
`LastRemovalDate` 能给出**设备离开 USB 总线的精确时刻**，
从而把设备异常**唯一归因到某一次开火窗口**。本轮正是靠它才把责任定位到 H90。

配套：`analysis/scratch/pnp_snapshot.sh`（落盘式取证，无 stdout 依赖）。
