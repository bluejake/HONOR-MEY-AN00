## 三、★ 覆盖率缺口（必须诚实说明）

### 3.1 sessions 表 146 行，但 session_usage 只有 14 行

```
sessions 总数        = 146
session_usage 行数   = 14   ← 覆盖率 9.6%
used>0 的行          = 13
```

**含义**：WorkBuddy 会在会话归档/清理时删除 `session_usage` 行。**已清理会话的 token 用量在本地无任何记录。**

### 3.2 121 个 session 的 cwd 已被清空

```
sessions 按 cwd 统计：
  ?  (空)                     121   ← 已清理，归属不可判
  C:/.../2026-09-26-09-04-37    6   ★ 本项目
  其他 6 个工作区               19
```

⇒ **无法通过 cwd 判定那 121 个会话里有多少属于本项目。**

### 3.3 标题索引几乎不可用

用 20 个项目关键词（MEY / 43499 / 64560 / root / 提权 / 内核 / kernel / rb_erase / Dirty / Ghost / sm8735 …）扫 146 个 session 标题，**只命中 4 个**：

| 时间 | 标题 |
|---|---|
| 08-15 17:16 | 对荣耀500利用cve43499进行root |
| 09-08 22:31 | ankidroid在荣耀500导出是空白卡…（**非本项目**） |
| 09-30 16:12 | MEY-AN00 |
| 10-05 10:15 | 询问手机利用CEV-2026-43499提权 |

⇒ 标题要么被截断、要么未索引，**不能作为归属判据**。

### 3.4 结论：166 万是**下界**，不是总量

| 情形 | 判断 |
|---|---|
| 8-15 首个 session（「对荣耀500利用cve43499进行root」） | **很可能已清理** ⇒ 该轮 token 不在统计内 |
| 9 月密集期（129 个 session，其中大部分已清理） | **绝大部分 token 不在统计内** |
| 可见的 6 个 session 覆盖 9-26、9-30、10-02、10-06 | 只是几个"高峰尾巴" |

## 四、粗略外推（★ 仅供参考，非实测）

用**可见比例**做两种外推：

### 4.1 按 session 数外推

```
本项目可见 session = 6
全部 session       = 146
覆盖率            = 4.1%
可见 token        = 1,661,007
外推总量          ≈ 1,661,007 / 0.041 ≈ 4,050 万 token
```

### 4.2 按时间覆盖外推

```
项目跨度         = 08-15 ~ 10-06（约 52 天）
有 usage 记录的  = 09-26、09-30、10-02、10-06（4 个日期）
时间覆盖率       ≈ 4/52 = 7.7%
外推总量         ≈ 1,661,007 / 0.077 ≈ 2,157 万 token
```

### 4.3 两个外推的差距很大

| 方法 | 外推值 |
|---|---|
| 按 session 数 | ≈ **4,050 万** |
| 按时间天数 | ≈ **2,157 万** |
| **取区间** | **≈ 200 万 ~ 400 万 token** |

⚠️ **两个外推差 2 倍，且都建立在「归档会话的用量分布与可见会话相似」这个未经验证的假设上。可信度低，仅作数量级参考。**

★ **已排除的路径**：
- `assistant-display/*.json` → 结构为 `{version, snapshots}`，**无 token 字段**（已 grep 验证 0 命中）
- `audit-log/*.jsonl` → 是操作审计，不是模型调用计量
- `cache/acc-product-config-*.json` → 命中 `usage` 字段但**是产品配置模板**，非真实用量

## 七、一句话回答

**能统计到的部分：本项目 ≈ 166 万 token（6 个会话）；真实总量估计在 200 万~400 万，但因 146 个会话中 92% 的 usage 记录已被清理，无法给出准确值。**

**建议用「43 天 / 251 轮 / 42 次重启 / 190 万次 MISS / 308,610 行代码」这组硬指标衡量成本，它们比 token 更可靠也更直观。**
