# 固件获取说明

> **本仓库不包含任何固件镜像。**
> 原始工作区的固件数据约 **350 GB**（`firmware*`、`fw/`、`adapt_batch/` 等），
> 远超 GitHub 限制（单文件 100 MB / 仓库软限约 1 GB），且厂商固件的再分发受其分发条款约束。
> 请自行从官方渠道获取。

## 需要哪些分区

研究/复现通常需要以下分区镜像：

| 分区 | 用途 |
|---|---|
| `boot` / `init_boot` | 内核 Image + ramdisk；符号表与偏移的主要来源 |
| `vendor_boot` | vendor ramdisk / DTB |
| `dtbo` | 设备树叠加层 |
| `vbmeta` | 验证启动元数据（用于分析，非绕过） |

## 获取途径（请优先选择合法来源）

1. **官方固件包**：厂商公开的升级包 / 官方售后固件。
2. **自有设备提取**：在你自己的设备上，通过已授权的方式（如官方下载模式、厂商提供的工具）读取分区。
3. **OTA 包**：设备接收到的官方 OTA 更新包。

请勿从第三方站点下载来源不明的固件 —— 可能被植入后门。

## 提取后如何用本仓库的工具分析

`tools/analysis/` 下提供了用于固件与内核分析的脚本，例如：

- 内核镜像 → ELF / 符号表恢复
- bootconfig / kernel 配置解析
- 结构体偏移与补丁状态比对

具体用法参见各脚本头部注释与 `docs/research/` 中对应的研究报告。

## 关于再分发

如果你在分析后希望分享成果，**请分享脚本、偏移表与结论，而不是固件镜像本身**。
本仓库的 `docs/research/` 与 `src/*/target*.h` 即是这种「只分享结论」的实践示例。
